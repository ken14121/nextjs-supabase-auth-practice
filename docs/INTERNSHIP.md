# 実習の進め方メモ

Zendash 臨地実務実習の報告ルール・時間管理・前任者の記録から分かったことをまとめたものです。
開発の手順は [ROADMAP.md](ROADMAP.md) を参照。

> 報告・時間・日報のルールは、実習開始時に先生から Slack で届いた「実習の進め方覚書」に基づいています。

## 基本情報

- 開始: 9/28
- 形態: フルリモート
  - 学校の方針: 全体の **1/3 程度は学内**で作業する（場所の決まりはなし。自習室や PC ルームなど）
  - 先生の方針: **最低週 1 日はコクーン**で作業する（2 日以上でも可）
- 合計時間: **225 時間以上**（超える分には構わない。足りないことがないよう自分で積算する）
  - 1 日 7.5 時間ペースで **約 30 日 ≒ 6 週間**
- 担当: 吉田先生（学校側）/ ゆうへいさん（Zendash 側、Slack 表示名 Yuhei）
- 質問は Slack の該当メッセージのスレッドで聞く
- Slack は昼間つながりにくく、返信は夜になることが多い
- 時間は自分で管理する。勤務時間は比較的自由だが、業務中の連絡にはきちんと反応する
- 9/28 の開始前に「こんなものを作って」という指示が来る（内容は自由、技術は多少指定あり。指示が来たら ROADMAP.md を合わせて直す）
- 最終的な成果: Jev を使ったアプリを GitHub Pages で紹介してポートフォリオにする。余裕があれば Syllabuzz の改善案をユーザー目線でまとめ、さらに余裕があればコードで修正する

## 毎日の報告（Slack のチャンネル）

業務の開始と終了を、そのつどチャンネルに報告する。

- **開始**: 作業場所（在宅 / コクーン / 学内）を必ず書く。時刻を書かなければ、投稿した時刻で判断される
- **終了**: 作業場所は書かなくてよい
- **決まり以上に休憩した**ときは、終了報告に書き足す

```
在宅にて業務開始
```

```
8:00 コクーンで業務開始
```

```
18:30 業務終了（14:00〜14:30 私用で離席）
```

- 終了報告を忘れたら、気づいた時点で「◯:◯◯に業務終了していました」と送る

## 作業時間の数え方

1. **12:00〜13:00 は自動で昼休み**。12:00 に始めても 13:00 開始扱い
2. 昼休みを除いた時間が **7.5 時間を超えたら、さらに 30 分の休憩**が自動で入る
3. 決まり以上に休憩したら、その分も引く（終了報告で申告）

| 開始〜終了 | 昼休みを除く | 記録 |
| --- | --- | --- |
| 9:00〜17:30 | 7 時間 30 分 | **7.5 時間** |
| 9:00〜18:00 | 8 時間 00 分 | **7.5 時間**（30 分休憩が入る） |
| 9:00〜18:10 | 8 時間 10 分 | **7 時間 40 分** |
| 9:00〜18:30 | 8 時間 30 分 | **8.0 時間** |
| 8:00〜18:00 | 9 時間 00 分 | **8.5 時間** |

7.5 時間を少し超えても 30 分引かれるので、**7.5〜8 時間の範囲はすべて 7.5 時間扱い**になる。

## 日報・週報（毎週金曜に提出）

日報は毎日付け、**毎週金曜の業務終了後**にまとめてチャンネルに提出する。前任者は Word の週報形式で出していた。**合計作業時間**も書いておくと喜ばれる。スクリーンショットを 1 枚付けるとなお良い。

- 上部: 氏名 / 提出日 / 対象期間 / 企業様（Zendash様）
- 日次作業記録: 日付 / 作業内容 / 作業時間
- 最下行: 合計作業時間

作業内容は 2〜4 行で、次の順に書くと伝わりやすい。

1. やったこと・できたこと
2. 詰まったこと → 原因 → どう対処したか
3. 次にやること

### 日報メモ（毎日ここに書いておき、金曜に週報へ写す）

```
## 9/28(月) 在宅 9:00〜18:30（8.0時間）
- やったこと:
- 詰まったこと（原因 / 対処）:
- 次にやること:
- スクショ候補:
```

## 最終日: 総括レポート

Markdown で渡すか、記事にして公開する。次の人への引き継ぎ資料にもなる。

- 何を作ったか
- 週ごとのタイムライン（週報をもとにまとめる）
- 詰まったところまとめ
- 最終日時点でできること
- 引き継ぎ事項（残っている課題 / 必要な環境変数・設定 / 主要ファイル）

加えて今回は、**GitHub Pages で「Jev をこう使った」を紹介するページ**を作ってポートフォリオにする。

## Zendash 側が見ているところ（前任者へのコメントより）

- **何を作るかを早めに決めて共有する**（2 日目に質問されていた）
- 自分が実際に使う、実用的なものが良い
- **DB を使って双方向にやり取り**できるようにする
- **検索機能**を入れる。何を検索しているのか（範囲）が分かる検索バーにする
- 週報にスクリーンショットを 1 枚付ける

## 前任者の記録から学んだこと

| 起きたこと | 今回の対策 |
| --- | --- |
| ログイン後に 404。原因は Supabase のセッション | `proxy.ts` でのセッション更新を公式手順どおりに書き、仕組みを理解してから進める |
| 外部 API（電車データ）の登録が 2 週間以上通らず断念 | **Jev のアカウント作成・API 疎通を初日に確認する**。待ちが出たら別の作業を進める |
| Google ログインが用途に合わず、途中で GitHub ログインに変更 | ユーザーごとにデータが分かれるアプリにして、ログインに意味を持たせる |
| コメントが匿名、誰でも編集・削除できる状態で終了 | **テーブルを作った時点で RLS を書く**。「自分のデータだけ」を最初から守る |
| AI API の動作確認を繰り返して利用上限に到達 | 開発中は結果を DB に保存して使い回す。同じ入力で何度も呼ばない |
| アプリを 2 つに広げて、どちらも途中で終了 | **1 つのアプリを最後まで仕上げる**。追加したいものは「やりたいことリスト」に書いておく |
| UI 作りで「あれもこれも」となり時間がかかった | 1 画面ずつ、最小限の見た目で機能を先に動かす |
