# Jev の使い方と、そう決めた理由

GitHub Pages の紹介ページ（「Jev をこう使った」）の下書きを兼ねる。

## 何に使っているか

タイムラインから取り込んだ外出 1 回ずつを「旅行 / 帰省 / 日帰り / 日常」に分ける。
日常以外は「旅の一覧」と友達との比較に出る。日常は友達に見せない。

## 送っている中身（`lib/jev/state.ts`）

Jev は計算が苦手なので、数えられるものはコードで先に計算し、日本語の JSON にして渡す。

- 出発・帰宅の日付と曜日、泊数、移動した距離、主な移動手段
- 行った場所ごとの「これまでに行った日数」「よく行く場所か（30 日以上）」
- 住んでいる都道府県（一番多く行った都道府県）
- 時期（年末年始・ゴールデンウィーク・お盆）

## 聞き方：4 択ではなく「はい / いいえ」2 つ（`lib/jev/classify.ts`・`decide.ts`）

```
日常か？（Jev・Noul）──はい──→ 日常
   │いいえ
泊まったか？（コード）──いいえ──→ 日帰り
   │はい
帰省か？（Jev・Noul）──はい──→ 帰省 / いいえ → 旅行
```

- はじめは Choice（4 択）で聞いていた。
- 記事「TypeSafe の Jev を正しく驚く、それって LLM でできませんか？」のコメント欄で、
  **結果の分からないサイコロの目を Choice で聞くと 400 回すべて 1 つめの選択肢を選び、確率も平均 83% と出た**
  （本来は 1/6）。一方、Noul（はい / いいえ）で聞くと 1/6 に近い値だった、という検証が紹介されていた。
- 4 択だと並び順で答えが偏るおそれがあるので、Noul 2 問に分けた。泊数のように数えれば分かることは Jev に聞かない。
- 2 問は 1 回の通信でまとめて送り、Jev の中で同時に判定されるので、回数・待ち時間はほぼ変わらない。

## 確率の扱い

- Jev は「較正された（現実と一致する）確率」を返すとしているが、上の検証のように崩れる場合もある。
- そこで、画面には確率の数字を大きく出さず、**70% 未満のときに「要確認」と出す**ことにだけ使う
  （数字はカーソルを合わせると見える）。
- 本人が選び直した判定は `label_source = 'user'` として残り、Jev が上書きしない。
  あとで「Jev の判定」と「本人の答え」を比べれば、このアプリでの正解率や、確率がどれくらい当てになるかを確かめられる。

## 料金・回数の節約

- 判定済み（`label` が入っている）外出は二度と送らない。1 回のボタンで 20 件まで、同時に 4 件ずつ。
- API キー（`JEV_API_KEY`）はサーバーだけで使う。`lib/jev/classify.ts` に `import "server-only"`。
