# Jev の使い方と、そう決めた理由

GitHub Pages の紹介ページ（「Jev をこう使った」）の下書きを兼ねる。

## 何に使っているか

タイムラインから取り込んだ外出 1 回ずつを「旅行 / 帰省 / 日帰り / 日常」に分ける。
日常以外は「旅の一覧」と友達との比較に出る。日常は友達に見せない。

## 送っている中身（`lib/jev/state.ts`）

Jev は計算が苦手なので、数えられるものはコードで先に計算し、日本語の JSON にして渡す。

- 出発・帰宅の日付と曜日、泊数、移動した距離、主な移動手段
- 行った場所ごとの「これまでに行った日数」「よく行く場所か（30 日以上）」
- 住んでいる都道府県（一番多く行った都道府県）
- 時期（年末年始・ゴールデンウィーク・お盆）

## いつもの場所か、ふだん行かない場所か（`lib/timeline/features.ts`）

都道府県だけだと、「東京の学校に行った日」と「渋谷に遊びに行った日」が同じ「東京都（300 日）」に見えて区別できない。
そこで取り込みのときに、タイムライン全体から「その地点の 500m 以内に何日行ったか」を数え、

- 10 日以上 → いつもの場所（学校・バイト先・最寄り駅など。自分で登録しなくても見つかる）
- 4〜9 日 → ときどき行く場所
- 3 日以下 → ふだん行かない場所

として、外出ごとにそれぞれの滞在時間と、自宅から一番遠い地点の距離を保存する（`outings.features`。座標は保存しない）。

**泊まっておらず、ふだん行かない場所に 30 分未満・ときどき行く場所に 1 時間未満しかいない日は、Jev に聞かずにコードで「日常」と決める**（`label_source = 'rule'`）。
通学の日がほとんどなので、Jev に送る回数（クレジット）が大きく減る。サンプルでは 37 件中 24 件がこれで決まった。

## 聞き方：4 択ではなく「はい / いいえ」3 つ（`lib/jev/classify.ts`・`decide.ts`）

```
日常か？（Jev）──はい──→ 日常
   │いいえ
泊まったか？（コード）──いいえ──→ 遠くへの日帰り旅行か？（Jev）──はい──→ 日帰り / いいえ → おでかけ
   │はい
帰省か？（Jev）──はい──→ 帰省 / いいえ → 旅行
```

「おでかけ」は近場で遊ぶ・買い物・食事（例：都心の繁華街）。旅の一覧と友達への共有には入れない。

- はじめは Choice（4 択）で聞いていた。
- 記事「TypeSafe の Jev を正しく驚く、それって LLM でできませんか？」のコメント欄で、
  **結果の分からないサイコロの目を Choice で聞くと 400 回すべて 1 つめの選択肢を選び、確率も平均 83% と出た**
  （本来は 1/6）。一方、Noul（はい / いいえ）で聞くと 1/6 に近い値だった、という検証が紹介されていた。
- 4 択だと並び順で答えが偏るおそれがあるので、Noul に分けた。泊数のように数えれば分かることは Jev に聞かない。
- 3 問は 1 回の通信でまとめて送り、Jev の中で同時に判定されるので、回数・待ち時間はほぼ変わらない。

## 確率の扱い

- Jev は「較正された（現実と一致する）確率」を返すとしているが、上の検証のように崩れる場合もある。
- そこで、画面には確率の数字を大きく出さず、**70% 未満のときに「要確認」と出す**ことにだけ使う
  （数字はカーソルを合わせると見える）。
- 2 つの質問を通って決まる旅行・帰省は、2 つの確かさの**低い方**を使う。はじめは掛け算にしていたが、
  はっきりした 5 泊の旅行でも 0.85 × 0.8 = 0.68 となり「要確認」が付いてしまった（10/5 の本番の判定で気づいた）。
- 本人が選び直した判定は `label_source = 'user'` として残り、Jev が上書きしない。

## 正解率と確率の当てはまりを測る（`/outings/review`・`lib/jev/evaluate.ts`）

- Jev の元の答えは `jev_label`・`jev_confidence`・`jev_p_daily`・`jev_p_homecoming` に残し、本人が直しても消えない。
- 本人は「合ってる」か、正しい種類を選ぶ。どちらも「確かめた」に数える（合っていたことも記録しないと正解率が出せない）。
- 確かめる外出は**でたらめに選ぶ**（ID から決まる並び）。要確認だけを見ると正解率が低く出てしまうため。
- 出すもの
  - 正解率（Jev の答え = 本人の答え の割合）
  - 「要確認あり / なし」それぞれの正解率（要確認の目印が役に立っているか）
  - Jev の答え × 本人の答え の対応表（どの種類を取り違えやすいか）
  - 「日常か？」の確率を 20% ごとに分け、実際に日常だった割合と比べた表（確率の較正。正しければ平均と実際がほぼ同じになる）
- 件数が 50 件未満のうちは、数字がぶれると画面に注意を出す。

## 料金・回数の節約

**実際にかかった料金（10/5）**: 外出 20 件の判定（Jev への送信 20 回、1 回に質問 2 つ）で **$0.0007**。
1 回あたり約 $0.000035。残り約 360 件を全部送っても約 $0.013 の見込み。
（Zendash の共用アカウントで、上限 $5 を設定済み。上限に達すると止まる）


- 判定済み（`label` が入っている）外出は二度と送らない。1 回のボタンで 20 件まで、同時に 4 件ずつ。
- API キー（`JEV_API_KEY`）はサーバーだけで使う。`lib/jev/classify.ts` に `import "server-only"`。

## 本人の基準に合わせて質問を直す（10/8）

本人が 57 件を確かめた結果（質問を直す前）:

- 正解率 **75%**（要確認なし 83%・要確認あり 62%）
- いちばん多い間違いは「日常」と「おでかけ」の取り違え
  - Jev「日常」→ 本人「おでかけ」: 7 件（学校の前後に、いつもの場所以外で遊んだ日）
  - Jev「おでかけ」→ 本人「日常」: 4 件（家のすぐそば。バイトなどの可能性）
- 確率の当てはまり（「日常か？」）: 0〜20% → 実際 15%、40〜60% → 45%、80〜100% → 92%。
  Noul で聞いた確率は、思ったより現実と合っていた

直したこと:

- 家の近所（自宅から一番遠い地点が 5km 以内）だけの日は、Jev に聞かずに日常（`NEAR_HOME_KM`）
- 「日常か？」の質問に、本人の基準を言葉で書いた
  （いつもの場所以外に合わせて 1 時間以上いたら、学校の前後でも日常ではない、など）
- 「新しい質問で Jev に聞き直す」ボタン：確かめ済みの外出は Jev の答えだけ取り直し、
  **同じ外出で直す前と後の正解率を比べられる**ようにした

学んだこと: Jev に任せるときは、**判断の基準を先に言葉にする**必要がある。
「日常」「おでかけ」の境目は人によって違うので、本人の答えを見てから基準を書くと当たりやすくなる。
（学校のある街で遊んだ日は、記録だけでは学校の日と区別できない。ここは本人が直す前提）

## 直した質問で聞き直した結果（10/9）

同じ 57 件を、10/8 の質問（v2）で聞き直した結果:

| | v1（10/8 朝） | v2（10/8 夕方） |
|---|---|---|
| 正解率 | **75%** | **58%** |
| 要確認なし / あり | 83% / 62% | 63% / 44% |
| Jev「日常」と言った数 | 32 件 | 8 件 |
| 本人「日常」なのに Jev「旅行」 | 1 件 | **11 件** |
| 本人「日常」なのに Jev「おでかけ」 | 4 件 | 11 件 |
| 「日常」の確率 0〜20% と言った数 → 実際に日常 | 13 件 → 15% | **42 件 → 36%** |

- **下がった。** 「日常」の取りこぼしが一気に増えた（Jev「日常」と言ったものは 8 件すべて当たり）
- 原因: 「いつもの場所以外での滞在が合わせて **1 時間以上**なら日常ではない」と**数字の線**を書いたこと
  - Jev はこの線をそのまま守った。ふつうの日でも、ときどき行く場所（友人の家・乗り換えの駅など）を足すと 1 時間はすぐ超える
  - 泊まりの日（学校や友人宅に泊まった日）も「1 時間以上」に引っかかり、「日常ではない → 泊まりなので旅行」になった
  - 確率の当てはまりも崩れた（0〜20% と言ったのに 36% が日常）。基準に当てはまるかどうかは自信を持って答えるので、**基準そのものがずれていると、自信を持って外す**
- 「1 時間」は本人の言葉ではなく、本人の話（学校の後に新宿で遊ぶこともある）を Claude が数字に置き換えたものだった

直したこと（v3）: 質問を v1 の書き方に戻し、「自宅の近くでの用事は日常」だけを足した。
家の近く（5km 以内）だけの日は、Jev に聞く前にコードのルールで日常に決まる（これは v2 から続けて使う）。

学んだこと: **Jev は書かれた基準を文字どおりに守る。** あいまいな境目に、本人が言っていない数字の線を引かない。
基準を変えたら、同じ外出で聞き直して**必ず前後を比べる**（今回は比べたので、悪くなったことにすぐ気づけた）。

### v3 で聞き直した結果（10/9）

| | v1 | v2 | v3 |
|---|---|---|---|
| 正解率 | 75% | 58% | **77%** |
| 要確認なし / あり | 83% / 62% | 63% / 44% | 85% / 61% |
| 本人「日常」なのに Jev「旅行」 | 1 | 11 | 2 |
| 本人「日常」なのに Jev「おでかけ」 | 4 | 11 | 6 |
| 本人「おでかけ」なのに Jev「日常」 | 7 | 0 | 3 |

- v2 の失敗は取り戻せた。v1 との差（75% → 77%）は 57 件のうち 1 件ぶんなので、**ほぼ同じ**と見る
- 確率の当てはまりは v1 と同じくらい良い（0〜20% → 実際 7%、80〜100% → 100%）。
  ただ 40〜60% と言った 8 件は実際には 88% が日常で、真ん中の確率は「日常」寄りに外れている
  （50% を境目にしているので、ここが「おでかけ」側の取り違えになりやすい。件数が少ないので境目はまだ動かさない）
- 聞き直しでは、確かめ済みの外出をすべて Jev に聞いている。実際のアプリは家の近く（5km 以内）・いつもの場所だけの日を
  Jev に聞く前にルールで日常にするので、確かめるページに「ルールも含めた正解率」も出すようにした
