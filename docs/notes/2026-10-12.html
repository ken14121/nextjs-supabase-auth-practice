01

きっかけ：AI が作りがちな UI

ゆうへいさんから「UI は AI に特に指示なく任せると、AI が作ったよくある UI になりがち。自分なり（プロダクトなり）の UI を考えてみると良い」と助言をもらった。コードで確かめると、本当に初期設定のままだった。

ところ前の状態
色shadcn の初期設定のまま、白・黒・グレーだけ。色があるのは地図だけ
文字英字用のフォント（Geist）の設定のまま。しかも設定が自分自身を指していて、実際は効いていなかった
形どのページも、グレーの背景に角の丸い白いカードを縦に並べる。マイページだけでカードが 15 枚
タブの名前「Create Next App」（雛形のまま）

初期設定のまま残っている所が「AI っぽさ」の正体だった。一つひとつは小さいが、全部そろうと「どこかで見た画面」になる。

02

方向を決める

いきなり作り直すと、結局「AI が決めた UI」になる。そこで、同じ中身のマイページを 3 つの雰囲気で並べた見本を作り、好き・嫌いを言葉にする材料にした。

案雰囲気結果
A 地図帳紙と黒い罫線、明朝体、朱色 1 色これに決定
B 切符乗車券の形、スタンプ、深緑と赤
C 夜の地球儀黒地に細い線、金色 1 色

参考に、市町村ごとの「経験値」（宿泊・訪問・接地・通過）で塗った踏破地図と、記録がぎっしり並んだ個人のページも見つけた。明朝体と罫線の表で、自分のための記録帳という雰囲気が地図帳の方向と合う。市町村の踏破地図や経県値は、次の機能の候補にした。

決めることは「名前と言葉」「色」「文字」「形」「マイページの中身」「経験値」の 6 分類・33 項目。全部に仮の案を書き、決まるまで仮の案で作り進める。友達との比較の 3 色は、色覚の違いがあっても見分けやすい今の色（青・橙・緑）のままにすると決めた。

03

地図帳の見た目のルール

ルール中身どこで決めているか
色紙 #f6f3ec（生成り）、墨 #1d1c1a（文字と罫線）、朱 #c8432c（差し色）。行った日数の塗りも朱の濃淡app/globals.css、lib/geo/visited-colors.ts
文字見出しと数字は明朝（しっぽり明朝）、本文はゴシック（Zen 角ゴシック New）app/layout.tsx（next/font）
形白い角丸のカードをやめ、太い墨の罫線と余白で区切る。角はほぼ四角（2px）components/ui/card.tsx
タブ・帯丸い箱ではなく、文字と下線。選んでいるものに朱の下線components/ui/tabs.tsx、components/site-nav.tsx
名前仮に「旅の地図帳」。ここを直すと全部変わるlib/app-name.ts

ルールを 1 か所（色の変数・カードの部品）にまとめておいたので、各ページを書き直さなくても、全ページの見た目が一度に変わった。

04

わたしの地図帳

  • 「30 / 47 都道府県」を大きく。その下に、国・外出・旅の数
  • 地図（日本・世界）と、地図帳の索引のような「最近の旅」（日常は出さない）
  • メールアドレスは出さない。名前・フレンドコード・ログアウトは一番下の小さな欄に
  • まだ判定していない外出があるときだけ、「記録の整理へ」の一文を出す
  • 全ページの上に細い帯（地図帳・旅の索引・友達・地球儀・記録の整理・取り込む）。今いるページに朱の下線
  • 「要確認」は赤い文字ではなく、「？」と点線の下線にした（朱は行った場所の色なので、意味がぶつからないように）
05

世界は回せる地球儀

描き方
d3 の正射図法（geoOrthographic）で、ブラウザの中で描く。回す角度（rotate）を変えるだけで地球が回る
操作
ドラッグや矢印キーで回す。拡大はしない。触っていないあいだはゆっくり自転し、動きを減らす設定の人には自転させない
データ
国の形（約 160KB）は /geo/countries（ビルド時に作る静的な JSON）を、世界のタブを開いたときに読み込む
小さな国
粗い地図に形がない国（シンガポールなど）は、地球の表側に来たときだけ中心に点を打つ
使い回し
地図帳と友達との比較で同じ部品（WorldGlobeMap）を使う。使わなくなった平らな世界地図のコードは消した

つまずいたことと学び

起きたこと原因対処
作り直したマイページの見た目を、こちらで確かめられないログインしないと見られないページで、データも Supabase から取っていた表示の部分（AtlasView）とデータの取得（page.tsx）を分け、架空のデータを渡して確かめた
見本の地図が真っ黒になったSVG の <use> で使い回した形には、.jp .p のような「外側から」の CSS が当たらない使い回す元の形（#jp .p）に色を指定し、色の値は外側から変数で渡す
ビルドが 1 回だけ失敗した日本語のフォントをビルドのときに Google から取ってくるが、通信が一時的に失敗したもう一度ビルドして通った（フォントの設定の問題ではない）
07

理解度チェック

  1. 「AI が作りがちな UI」になっていた原因は何だった？

    答えを見る

    初期設定のまま残っている所。白・黒・グレーだけの色、効いていないフォント、どのページも角丸の白いカード、雛形のままのタブの名前。一つひとつは小さいが、全部そろうと「どこかで見た画面」になる。

  2. すぐに作り直さず、先に 3 案の見本を作ったのはなぜ？

    答えを見る

    いきなり作ると、結局 AI が決めた UI になるから。同じ中身を違う雰囲気で並べると、「ここは好き」「これは違う」を言葉にでき、自分で方向を決められる。

  3. 各ページを書き直さなくても、全ページの見た目が変わったのはなぜ？

    答えを見る

    色は CSS の変数（globals.css）、カードやタブは共通の部品（components/ui）にまとめてあったから。ルールを 1 か所で直せば、使っている全ページに効く。

  4. 「要確認」の目印を赤い文字から「？」と点線の下線に変えたのはなぜ？

    答えを見る

    差し色の朱は「行った場所」の色に使っているので、赤い文字だと意味がぶつかって見分けにくい。色ではなく記号と線で示した。

  5. 地球儀の国の形を、ページと一緒ではなく、世界のタブを開いたときに読み込むのはなぜ？

    答えを見る

    約 160KB あり、日本地図だけ見る人には要らないから。ビルド時に作った静的なファイルなので、一度読めばブラウザにも残る。

  6. ログインが必要なページの見た目を、架空のデータで確かめられるようにした工夫は？

    答えを見る

    データを取る部分（page.tsx）と、表示だけをする部品（AtlasView）に分けた。表示の部品にはデータを引数で渡すので、架空のデータを渡せば同じ見た目が出る。
