02

エラー：ブラウザの翻訳とぶつかって落ちる

プロフィールの「AI コース推奨」で「デモ結果の生成」を押すと、毎回、黒い全画面のエラー「何かがうまくいかなかった」になった。下に NotFoundError（Failed to execute 'removeChild' on 'Node'）と出ていた。

試したこと結果
Edge の「ページの翻訳」オン（日本語で表示）毎回エラー
翻訳オフ（英語のまま）エラーにならず、おすすめが出た

ブラウザの翻訳は、ページの文字を勝手に書き換える。React は「自分が作った画面の部品」を覚えていて、それを消そうとしたときに、翻訳で差し替えられていて見つからず、落ちる。

改善案：① 翻訳されても壊れないつくりにする　② 落ちたときに技術的な中身（NotFoundError の生のデータ）を利用者に見せない　③ 自前の言語の切り替えを用意して、ブラウザの翻訳に頼らせない
03

分かりづらかった点

場所起きたこと改善案
左のプロフィールカード名前などの文字の上を押すと、移動せずに文字が選ばれて（反転して）しまう。右上のアイコンからだと移動するカード全体を 1 つのリンクにする／カードの文字を選べないようにする（user-select: none）
コース一覧の並び替え「レビュー」から「Rating」に変えても、コースを 1 つ開いて戻ると「レビュー」に戻る選んだ並び順を覚えておく（URL に並び順を付ける、など）
04

良かった点（なぜ分かりやすいか）

  • キャンパス・コンパス：到着前 → 最初の週 → 住まい → 引っ越し → お金 … と、着く前から着いた後までが時系列に並び、中に入るとすぐ見られる要点のまとめ、注意点、提出先の URL がそろっている
  • 検索：今いる場所に合わせて探す範囲が変わる。コースのページではコース名だけ、ホームでは全体から探せる

良かった点も「なぜ」まで分けて書くと、ほかのページへの改善提案に使える（例：エラーが出たページにも「順番・要点・注意点・リンク」の形を使う）。

05

やらないと決めたこと

コードを入れて試す
入力欄に JavaScript を入れて動くか試す（XSS）のは、頼まれた範囲（使いやすさとエラーの報告）を超えるので、やらない。許可の無い攻撃は、練習でも相手のサーバーで動いてしまう。ふつうに使っていて見つけた入力のおかしさだけを書く
重さの測定
ページの重さを測った（サーバーの応答は 0.2〜0.5 秒と速く、ブラウザに送る JavaScript が約 2 MB）。ただ、報告には入れないことにした
06

理解度チェック

  1. 翻訳オンのときだけ removeChild のエラーが出たのはなぜ？

    答えを見る

    ブラウザの翻訳がページの文字を書き換えるので、React が覚えている部品と実際の画面が食い違い、消そうとした部品が見つからなかったから。

  2. エラーの報告に「何回中何回出たか」を書くのはなぜ？

    答えを見る

    毎回出るのか、たまにしか出ないのかで、直す人の調べ方が変わるから。条件を変えて（翻訳オン／オフ）比べると、原因まで絞れる。

  3. 気づいたことを、触りながらその場でメモするのはなぜ？

    答えを見る

    あとから思い出すと、使い方に慣れたあとの目で書いてしまい、初めての人がつまずくところを忘れてしまうから。

  4. 入力欄に攻撃用のコードを入れて試さなかったのはなぜ？

    答えを見る

    頼まれたのは使いやすさとエラーの報告で、脆弱性を試す許可はもらっていないから。他社の本番サイトに許可なく攻撃コードを送るのは、規約違反や違法になることがある。

やったこと：メインの自分のアプリ（旅の地図帳）は昨日公開できたので、今日は Syllabuzz のフィードバックを進めた。LP とデモを初めて触る人の目で触り、気づいたことを docs/syllabuzz/feedback.md にまとめた。分かりづらかった点（プロフィールカードの文字を押すと移動せず選択されてしまう／コースの並び順を変えても戻ると初期値に戻る）と、エラー（AI 推奨の「デモ結果の生成」で全画面エラーになる）を記録した。良かった点も、キャンパス・コンパス（着く前から着いた後までが時系列＋要点＋注意点＋手続きのリンクでまとまっている）と、場所に合わせて探す範囲が変わる検索を挙げた。

学んだこと：初めて触る人の第一印象（どこで迷うか）は、慣れる前にその場でメモするのが大事。エラーは「どこで・何をして・再現するか」をそろえると、原因と改善案まで書ける。良い点も「なぜ分かりやすいか」まで分けて書くと、改善提案に使える。
