01

どこに置くか（Vercel と GitHub Pages）

はじめは GitHub Pages で公開するつもりだったが、GitHub Pages は決まったファイル（HTML・画像など）を配るだけで、サーバーで動く処理は動かせない。

置くもの置く場所理由
アプリ本体Vercelログイン・Server Actions・判定など、サーバーで動く処理がある。Next.js を作っている会社のサービス
紹介ページGitHub Pages文章と画像だけの静的なページなので、こちらで足りる

だれでもログインできるようにする（Google のログイン画面を「本番環境」にする）ことと、Jev は自分だけにすることを決めた。

02

約束のページと、全部消す機能

トップページ
「行った場所が、地図帳になる。」。できること 3 つと、位置情報の扱い（座標は保存しない、ファイルは小さくしてから送り、調べ終えたらすぐ消す）
/privacy
何を保存し、だれに見えるか。友達に見えるのは表示名と、旅行・帰省・日帰りで行った県・国と日付だけ。メールアドレスはほかの人に見えない
削除の流れ
保存した画像（Storage）を消す → delete_my_account() でユーザーを消す → 外出・切符・友達などは連鎖して消える（cascade） → ログアウトしてトップへ
delete_my_account
security definer の関数。ログインしている本人（auth.uid()）しか消せず、ログインしていない人は呼べない
03

Jev を使えるのは本人だけ

Jev はお金がかかるので、公開サイトでだれでも使えると、知らない人にクレジットを使われてしまう。

  • JEV_OWNER_USER_IDS（サーバーだけの環境変数）にユーザー ID を書いた人だけが Jev を使える
  • 書いていなければ、だれも使わない（設定を忘れても、お金がかかる側に倒れない）
  • ほかの人はルールで判定する。画面のボタンも「Jev で判定」ではなく「判定する」になる
04

公開前の安全面のチェック

別のエージェントに、アプリ全体を「他人のデータを読み書きできる経路が無いか」の目で見てもらった。

見たこと結果
他人の外出・切符・設定を読める／書ける経路無し（RLS と列ごとの権限で守られている）
リポジトリに秘密の値が入っていないか無し。service_role のキーも使っていない
帰省の設定の保存（upsert）不具合あり：user_id を更新する権限が無く失敗する → 「更新して、無ければ足す」に直した
05

つまずいたことと学び

起きたこと原因対処
GitHub Pages ではアプリが動かないと分かったサーバーで動く処理があるアプリは Vercel、紹介ページは GitHub Pages に分けた
約束のページの説明が、実際の動きと違っていた「友達に見えるもの」を思い込みで書いていた（おでかけは見せていない・表示名は見える）コードを確かめて書き直した
安全チェックのコマンドが動かなかったorigin/HEAD が設定されていなかったgit remote set-head origin main
知らない人のデータを預かるときは、「何を保存して、だれに見えるか」を書き出して、コードと食い違いが無いか確かめる。書いてみたことで、説明のまちがいに気づけた。
06

理解度チェック

  1. このアプリを GitHub Pages だけで公開できないのはなぜ？

    答えを見る

    GitHub Pages はファイルを配るだけで、ログインや Server Actions のようなサーバーで動く処理を動かせないから。

  2. JEV_OWNER_USER_IDS が空のとき、だれも Jev を使えないようにしたのはなぜ？

    答えを見る

    設定を忘れたときに、全員が Jev を使ってクレジットが減る、という危ない側に倒れないようにするため（安全側に倒す）。

  3. アカウント削除で、外出や切符を 1 つずつ消さなくてよいのはなぜ？

    答えを見る

    表がユーザーに on delete cascade でつながっているので、ユーザーを消すと一緒に消えるから。Storage の画像だけは別なので、先に消す。

  4. 帰省の設定を、だれでも読めるプロフィールではなく別の表に置いたのはなぜ？

    答えを見る

    プロフィールは友達にも読めるから。帰省するかどうかは家庭の事情なので、本人しか読めない表にした。
