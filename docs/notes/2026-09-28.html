予習：Google ログインの流れ

  1. 1
    ユーザー

    アプリの「Google でログイン」を押す

  2. 2
    SUPABASE AUTH

    Google のログイン画面へ案内する

  3. 3
    GOOGLE

    「このアプリにログインしていい？」と聞き、ユーザーが許可する

  4. 4
    GOOGLE → SUPABASE

    「この人は本人です」と返す。ここで Google Cloud の OAuth クライアント ID を使う

  5. 5
    SUPABASE → アプリ

    ログイン済みの証明（Cookie）を渡す

  6. 6
    NEXT.JS（proxy.ts）

    ページを開くたびに Cookie を確認して、ログイン状態を保つ

Google Cloud は「このアプリが Google ログインを使ってよい」という許可証を出す役。Supabase はログインした人を覚えておく役。

予習：Jev のしくみ

入力と出力
  • 入力は State（判断材料の文章）と Questions（何を判断させるか）
  • 質問の型は 3 つ：Choice（選択肢から 1 つ）／ Score（点数）／ Noul（正しい確率）
  • 出力は選んだ答えと確率だけ。文章は書かない
注意点
  • 料金は入力だけにかかり、出力は無料
  • 計算や日付の比較は苦手。距離や泊数はこちらで計算して渡す
  • TypeSafe が 9/22 から新規登録を一時停止中。新しいアカウントに無料クレジットが付かず、Zendash 側で対応待ち

07

理解度チェック

まず自分で答えてから「答えを見る」を開く。

  1. package.json と yarn.lock の違いは？

    答えを見る

    package.json は「この部品を、このくらいのバージョン範囲で使いたい」という希望の一覧（例：typescript: ^5）。yarn.lock は実際に入った正確なバージョン（例：5.9.3）の記録で、誰がいつ入れても同じ部品になるようにする。

  2. node_modules/ を Git に入れないのはなぜ？ 入れなくても他の人が動かせるのはなぜ？

    答えを見る

    数百 MB と大きく、OS ごとに中身が違う部品もあるため。package.json と yarn.lock さえあれば、yarn install で同じものを入れ直せる。

  3. Google ログインで、Supabase と Google Cloud はそれぞれ何を担当する？

    答えを見る

    Google Cloud は「このアプリが Google ログインを使ってよい」という許可証（OAuth クライアント ID）を発行し、Google が本人確認をする。Supabase は Google から結果を受け取り、ユーザーを登録してログイン状態（Cookie）を管理する。

  4. 「自動 RLS: ON」にすると何が守られる？

    答えを見る

    新しいテーブルに最初から行ごとの鍵がかかり、ルール（ポリシー）を書くまではアプリ経由で誰も行を読み書きできない。ルールの書き忘れで全員のデータが丸見えになる事故を防げる。

  5. app/layout.tsx と app/page.tsx の違いは？

    答えを見る

    layout.tsx は全ページ共通の外枠（<html>、フォント、タブのタイトル）で、中の children に各ページが入る。page.tsx はその URL で表示される中身。

  6. yarn lint と yarn format の違いは？

    答えを見る

    yarn lint（biome check）は書き方のミスや整形のずれを見つけて報告するだけ。yarn format は字下げなどを実際にファイルへ書き直して整える。

  7. Jev に「東京から大阪まで何 km？」と聞くのが向いていないのはなぜ？

    答えを見る

    Jev は選択・点数・真偽の判定専用で、数値を計算して答える型がなく、計算も苦手だから。距離はコードで計算し、その結果を材料として渡して「旅行かどうか」を判定させる。
