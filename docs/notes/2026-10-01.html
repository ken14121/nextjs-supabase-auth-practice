マイページの 2D の地図

  1. 1
    境界データ（TopoJSON）

    都道府県は地球地図日本、国は Natural Earth。点の数を 92% 間引いて全国で約 70KB に軽くする（topojson-simplify）

  2. 2
    サーバー（d3-geo）

    緯度経度を画面の座標に変換（地図投影）して、SVG の <path> の文字列にする。地理のライブラリはブラウザに送らない

  3. 3
    ブラウザ

    できあがった SVG を表示するだけ。県にマウスを乗せると日数が出る（SVG の <title>）

色
青 1 色を薄い → 濃いで 4 段階（1 日 / 2〜4 日 / 5〜19 日 / 20 日以上）。色の違いが見分けられるか、ツールで確認した
沖縄県
本土から遠いので、左上の枠に別の縮尺で描く。大東諸島まで入れると島が小さくなりすぎるので、枠の外は切り取る（clipPath）

昔の旅の手入力（/trips）

フォーム
react-hook-form ＋ Zod。日付・種類（旅行 / 帰省 / 日帰り）・行った県（地方ごとのボタン）・国（検索して選ぶ）・メモ。「韓国」で「大韓民国」が出るよう、よく使う呼び方も検索対象にした
同じルールを 2 か所で
lib/trips/schema.ts の Zod スキーマを、ブラウザ（入力中のエラー表示）とサーバー（Server Action）の両方で使う。未来の日付・帰った日が出発より前・日帰りなのに日付が違う、などを弾く
DB の工夫
outings に source（timeline / manual）の列を追加。「同じ人・同じ開始時刻は 1 件」の制約はタイムライン取り込みの重複防止用なので、タイムライン由来のときだけ値が入る生成列 timeline_started_at に付け替えた。手入力の旅は同じ日に何件あっても大丈夫
編集できる範囲
手入力の旅だけ（source = 'manual'）。タイムラインから取り込んだ外出は書き換えられない

起きたこと原因対処
地図が真っ白（読み込みエラー）MapLibre 6 は裏で動く計算用のファイル（worker）を後から読みにいくが、Next.js のビルドに入らないyarn install のたびに public/maplibre/ へコピーするスクリプト（postinstall）を追加

コンソールに Failed to fetch: 404 が大量に出る標高タイルは海の上には無い。使っていたライブラリはそれを全部エラーにしていた変換処理を自作し、404 のときは高さ 0m の平らなタイルを返すようにした
タッチパッドで角度を変えられないMapLibre の回転・傾きは右ドラッグか Ctrl ＋ドラッグ前提モード切り替えとボタンを追加（上の 05）
yarn dev が 2 つ動いていた前に起動したものが残っていたtaskkill /PID 番号 /F で止めた

残っている calculateFogMatrix is not supported… などの 2 行は MapLibre の注意書き。地球儀表示では一部の機能が使えない、という意味で、動作には影響しない。

07

理解度チェック

  1. 操作モードを useState で持っているのに、同じ値を useRef にも入れているのはなぜ？

    答えを見る

    ドラッグやスワイプを受け取る関数は、地図を作ったときに 1 回だけ登録している。そのときの関数は、登録した瞬間のモードの値を覚えたまま（古い値のまま）になる。ref は「いつ読んでも最新の値が入っている箱」なので、イベントの中からでも今のモードが分かる。

  2. 3D の地図を dynamic(…, { ssr: false }) で読み込んでいるのはなぜ？

    答えを見る

    MapLibre は WebGL やブラウザの画面（window）を使うので、サーバーでは動かない。また、大きなライブラリなので、このページを開いたときだけ読み込めば他のページが重くならない。

  3. 3D の地図に、すべての国・都道府県ではなく「行った場所の形」だけを送るのはなぜ？

    答えを見る

    色を塗るのは行った場所だけなので、それ以外の形は要らない。送るデータが小さいほど早く表示できる。行っていない場所は航空写真がそのまま見えている。

  4. 手入力の旅のために、一意制約を timeline_started_at（生成列）に付け替えたのはなぜ？

    答えを見る

    「同じ人・同じ開始時刻は 1 件」はタイムライン取り込みの重複を防ぐためのルール。手入力の旅はどれも 0:00 開始なので、同じ日の旅が 2 件あるとぶつかる。生成列はタイムライン由来のときだけ値が入り、手入力では NULL になる。NULL どうしは「同じ」とみなされないので、手入力は何件でも入れられる。

  5. PLATEAU の建物データは日本中の建物が入った巨大なファイルなのに、地図がすぐ表示できるのはなぜ？

    答えを見る

    PMTiles は先頭に「どのタイルがファイルのどこにあるか」の目次を持っている。ブラウザは目次を読んでから、今見ている場所のタイルだけを範囲指定（Range リクエスト）で取りにいく。

  6. 手入力の旅のフォームで、ブラウザでチェックしているのにサーバーでも同じ Zod スキーマでチェックするのはなぜ？

    答えを見る

    ブラウザのチェックは使いやすさのため（すぐエラーが出る）。サーバーに届くデータは書き換えられている可能性があるので、守るためのチェックはサーバーで必ずする。スキーマを 1 つにしておけば、ルールが食い違わない。
