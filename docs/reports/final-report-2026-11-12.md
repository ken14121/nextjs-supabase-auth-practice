## 1. 実習の概要

フルリモートで、指定された技術（Next.js・Supabase・TypeScript など）と、LLM の判定器 Jev を使い、自分で決めたテーマの Web アプリを 1 つ作った。後半は、Zendash のサービス Syllabuzz を初めて使う学生の目で使って改善案を提出し、最後の週はメンターからの課題で SQL の基本に取り組んだ。開発では Claude Code（AI）を使い、出てきたコードは理由を聞き、自分で動かして確かめてから使うようにした。

## 2. 取り組んだこと

**旅の地図帳（Web アプリ）**：Google マップのタイムラインを読み込むだけで、行った都道府県・国・市区町村が地図に塗られ、旅が 1 回ずつ切符の形で一覧になり、友達と行った県を比べられるアプリを作った。位置の座標は保存せず、データベースのすべての表に行単位のアクセス制御（RLS）をかけた。市区町村ごとの踏破の地図や、行った国を回して見られる 3D の地球儀も作った。Vercel で公開し、だれでも Google アカウントでログインして使えるようにした。

**Jev による外出の仕分けと検証**：外出 1 回ずつを「旅行・帰省・日帰り・おでかけ・日常」に分ける部分に Jev を使った。距離や滞在時間などはコードで計算して渡し、判断だけを「はい／いいえ」で聞く形にした。自分の外出 81 件に正解を付けて比べ、質問の書き方・判定の境目・コードのルールとの組み合わせを試しながら、正解率を確かめた。

**Syllabuzz の改善提案**：デモと本番のサイトを初めて使う学生として触り、エラー・分かりづらい点・良かった点を、起きた場所・手順・再現の回数をそろえてまとめ、2 回提出した。代表の方とのミーティングでは、日本の学生のつながり方（Discord や Instagram が中心で、LINE はあまり使わない）などを、学生の目線で伝えた。

**SQL の学習**：SQL Quest と、企業のコーディング試験の問題に取り組んだ（1 週目で 53 問、平均 95 点）。

## 3. 成果

自分で正解を 2 回付け直すと、答えが 19% 変わった。この「本人どうしの一致」81% に対して、Jev は 77%、コードのルールは 74% で、どちらも人のぶれに近いところまで来た。また、Jev が「迷っている」と示した外出だけを見直せば、外れの 7 割を 3 分の 1 の手間で拾えることが分かった。この試行錯誤と応用のアイデアを、紹介ページ（GitHub Pages）にまとめた。

## 4. 苦労したこと・学んだこと

一番の失敗は、質問に「1 時間以上いたら日常ではない」と、自分が言っていない数字の線を書いたことだった。それだけで正解率が 75% から 58% に落ちた。AI は書かれた基準をそのまま守るので、あいまいな境目は数字ではなく、本人の言葉で伝えるべきだと学んだ。また、基準を決めたデータと同じデータで測ると数字が良く見えてしまうことや、正解そのものも人によってぶれることから、数字は条件と一緒に正直に出すことの大切さを学んだ。

公開の段階では、環境変数・ログインの設定・API キーの扱いなど、作ること以外の作業が多いことを知った。Syllabuzz の評価では、不具合を「どこで・何をして・何回中何回起きたか」までそろえると、相手に伝わり、改善案まで書けることを学んだ。また、そのサービスがだれに向けて作られているかによって、指摘すべきことが変わることも知った。実習の記録を公開のリポジトリに置いていたため、社外に出すべきでない記録を非公開の場所に移したことからは、公開する前に、どこに何が残るかを確かめる大切さを学んだ。

## 5. 今後に向けて

実習の前は、動くものを作ることに意識が向いていた。実習を通して、だれのデータを預かるのか、数字をどう測れば正直か、公開したあとに何が残るかまで考えて作るようになった。最後の週の SQL では、忘れていた基本を取り戻したうえで、実際の問題を解くことで、実務での使われ方やデータベースの管理の仕方まで自分の中に落とし込め、面接でも SQL の話ができた。

将来はバックエンドのエンジニアを目指している。今回、データベースの設計やアクセス制御には触れたが、SQL はまだ AI の助けを借りることが多い。実習のあとも SQL の学習を続け、自分で設計し、書いて説明できる力を付けたい。

最後に、6 週間にわたりご指導いただいた吉田先生、メンターの方、代表の安江様をはじめ、Zendash の皆様に感謝いたします。
