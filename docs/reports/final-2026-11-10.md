## 1. 何を作ったか

**旅の地図帳**：Google マップのタイムライン（スマホから書き出した Timeline.json）を読み込むだけで、今までの旅をふり返り、友達と行った県・国を比べられる Web アプリ。

- アプリ：https://nextjs-supabase-auth-practice.vercel.app/
- 紹介ページ：〔公開後の URL：https://ken14121.github.io/nextjs-supabase-auth-practice/〕
- ソースコード：https://github.com/ken14121/nextjs-supabase-auth-practice

主な機能：

- タイムラインを取り込み、行った都道府県・国・市区町村を地図に塗る（座標は保存しない）
- 外出 1 回ずつを「旅行・帰省・日帰り・おでかけ・日常」に分け、旅は 1 回ずつ切符の形（飛行機は搭乗券、新幹線は特急券など）で一覧にする
- 外出の仕分けは、コードで数えた材料をもとに、LLM の判定器 Jev（TypeSafe AI）に「はい／いいえ」で聞く。Jev を使えない人は、同じ材料のコードのルールで判定する
- 市区町村ごとの踏破（住居・宿泊・訪問・接地・通過の 5 段階）
- フレンドコードでつながった友達と、行った県・国を比べる
- 3D の地球儀（地理院の標高・PLATEAU の建物）
- 判定を確かめるページ（本人の答えと比べて、Jev とルールの正解率を出す）

使った技術：Next.js 16（App Router・Server Actions）、React 19、TypeScript、Tailwind CSS 4、shadcn/ui、react-hook-form・Zod、Supabase（PostgreSQL・Auth・RLS）、MapLibre GL JS、Jev、Biome、Playwright、Vercel、GitHub Pages。

## 3. 詰まったところまとめ

| 起きたこと | 原因 | どう対処したか |
| --- | --- | --- |
| 質問に「いつもの場所以外に 1 時間以上いたら日常ではない」と書いたら、正解率が 75% から 58% に落ちた | Jev は書かれた基準を文字どおり守る。その「1 時間」は自分の言葉ではなく、勝手に数字に置き換えたものだった | 数字の線をやめ、基準を言葉で書き直した（77%）。基準を変えたら、同じデータで前後を比べるようにした |
| 自分の答えを付け直したら、81 件中 15 件（19%）変わった | 「おでかけ」と「日常」の境目は、本人も迷う | 「その日の目的が用事なら日常、遊びならおでかけ」と基準を言葉にした。正解率は、人どうしの一致と並べて読む |
| ルールの正解率が、最初に言っていた 83% から、確かめ直すと 74% に下がった | 境目を決めたのと同じデータで測っていた | 交差検証（一部で選び、残りで測る）で、正直な数字（75% くらい）に直した |
| 友達にデータの協力を頼んだら、個人情報なので断られた | 位置の記録は人に見せたくないもの | データはもらわず、友達が自分のアカウントで確かめて、正解率の画面だけ送ってもらう形にした |
| 飛行機の取りこぼし・空港の間違い | 本物の記録には、サンプルに無い形があった | 本物の記録で試し、原因を調べてから直した |
| データベースの更新（`supabase db push`）が止まった | 家のパソコンのコードが古いままだった | エラーが勧めるコマンド（`migration repair`）は実行せず、手元を最新にしてからやり直した |
| Google のログイン画面の承認済みドメインに、`vercel.app` だけを入れても通らなかった | `vercel.app` はみんなで使う名前なので、自分のサブドメインまで必要 | 自分のサイトの名前まで登録した |
| アプリは GitHub Pages では動かない | ログインやサーバーで動く処理があるため | アプリは Vercel、紹介ページ（静的なページ）だけを GitHub Pages に分けた |
| 久しぶりの pull のあと、地図の線のデータが 404 になった | 古いビルドの保存データ（`.next`）が残っていた | `.next` を消して起動し直した（公開版は問題なし） |
| 新幹線で移動した区間の市区町村が「通過」にならず、抜けていた | 速い移動では、軌跡の点と点の間が 10km 以上空く | 点と点の間（50km まで）を直線で補うようにした |
| 公開リポジトリに、社外に出すべきでない記録を置いていた | リポジトリが公開で、ファイルを消しても履歴に残る | 履歴ごとバックアップしてから非公開のリポジトリに移し、作業ブランチを作り直した |

## 4. 最終日時点でできること

- だれでも Google でログインして、タイムラインを取り込み、地図帳・旅の索引・市区町村・地球儀・友達との比較を使える
- 外出の仕分け：本人は Jev（はい／いいえ 3 問）、ほかの人はコードのルールで判定する。Jev の答えには「要確認」が付き、判定を確かめるページで本人が直せる
- 確かめた結果（本人の外出 81 件、2 回目の答えで）：Jev 77%、アプリの流れ 78%、ルール 74%。本人どうしの一致は 81%。要確認なしは 91%、ありは 48% 当たる
- テスト：計算のテスト（unit）67 本、画面のテスト（e2e）。本物のデータベースや Jev には触らない
- 個人情報：位置の座標は保存しない。データベースの全部の表に、行単位のアクセス制御（RLS）をかけている。アカウントとデータは全部消せる
- 紹介ページ（`site/`）：正解率を上げるための試行錯誤と、Jev の応用のアイデアをまとめた。〔公開済みか〕

## 5. 引き継ぎ事項

### 残っている課題

- 「泊まりのおでかけ」（ネカフェで夜通し遊ぶ、友達の家に泊まる など）を判定できない。泊まると「帰省か旅行」にしか分かれないため（今の正解率の上限 91% はここから来ている）
- 自分以外のデータでの正解率が無い（友達に、判定を確かめるページを使ってもらう予定だった）
- 帰省・日帰りの外出は、確かめたデータに 1 件も無く、正解率が分かっていない
- 紹介ページの公開：プルリクエスト #4 のマージと、GitHub の Settings → Pages → Source を「GitHub Actions」にする設定〔済みなら消す〕
- 市区町村の補完は、取り込み直さないと反映されない
- Jev の記事（`docs/research/jev-report.md`）は〔要相談〕の所が残っていて、まだ外（Qiita など）には出していない
- GitHub Actions で lint とテストを自動で回す仕組みは、まだ無い

### 必要な環境変数・設定（くわしくは `docs/DEPLOY.md`）

| 名前 | 中身 | 注意 |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase の URL | |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase の publishable キー | `sb_secret_` や service_role のキーは絶対に入れない |
| `JEV_API_KEY` | Jev の API キー | サーバーだけで読む（`NEXT_PUBLIC_` を付けない）。無くても動く（全員ルールで判定） |
| `JEV_OWNER_USER_IDS` | Jev を使ってよい人の UID | 本人の UID 1 つだけ。空ならだれも Jev を使わない |
| `ENABLE_EXPERIMENTAL_COREPACK` | `1` | Vercel で Yarn 4 を使うため |

ほかの設定：

- Supabase：Authentication の戻り先（Redirect URLs）に、本番の URL を入れる
- Google Cloud：OAuth の同意画面を本番環境にし、承認済みドメインに自分の `vercel.app` のサブドメインまで入れる（ロゴは入れない。審査が要るため）
- Vercel：プロジェクトにほかの人をメンバーとして招待しない（環境変数のキーが見える）。Supabase の連携（Add）は押さない
- GitHub Pages：Settings → Pages → Source を「GitHub Actions」にする（`.github/workflows/pages.yml` が `site/` だけを公開する）
